Bumper speed toggle

Make one button press change a remembered drive mode.

Button state and speed

The exercise compiles, but holding the bumper causes the mode to change repeatedly. Diagnose why, add the missing button-state check, and retest.

See the problem

  1. Launch the simulator with the Android Studio Simulator run configuration.
  2. Select the preconfigured robot configuration and Teaching S2 Exercise - Speed Toggle.
  3. Press INIT and START. Drive briefly so you can recognize the normal control.
  4. Tap the right bumper once. Then hold it down. Watch the mode change rapidly instead of changing once.

Your repair

  1. Stop the OpMode and open SpeedToggleExerciseTeleOp.java in the Session 2 package.
  2. Use Search Everywhere with Shift+Shift, or navigate through the Project view.
  3. Find the pressed, wasPressed, and slow variables.
  4. Change the toggle condition so it runs only when the bumper is pressed now and was not pressed during the previous loop.
  5. Build and run the exercise again. A tap should change the mode once; holding the bumper should not repeat the change.
  6. Open SpeedToggleSolutionTeleOp.java and compare the edge-detection condition.

What the program remembers

loop() runs many times per second. A button can remain pressed across many loops, so checking only “is it pressed?” repeats the action. Comparing the current value with the previous value detects the transition from released to pressed.

StateMeaning
pressedWhat the bumper says during this loop
wasPressedWhat the bumper said during the previous loop
slowThe mode remembered by the program

What you should be able to explain

By the end of this lesson, every student should be able to explain why a held button is not the same as a button tap, use a previous-state variable to detect one press, and prove the fix with a simulator retest.

Test tap, hold, release, and tap again. Those four actions reveal whether the program is detecting a button state or a button transition.
